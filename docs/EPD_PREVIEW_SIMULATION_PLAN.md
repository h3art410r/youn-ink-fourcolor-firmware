# 刷机前屏幕预览：最小方案

## 目的

在修改墨水屏页面后、刷机前先生成一张电脑可查看的 400×300 四色预览，提前检查布局、遮挡、截断和颜色对比，减少“刷机—等待慢刷—再发现布局问题”的循环。

## 当前最小跑通

`firmware/tools/preview_weather.py` 可生成天气页的四颜色 PNG。它使用当前天气页的主要区域坐标、示例数据和黑/白/红/黄四种颜色，默认输出到固件构建目录下的 `preview/weather.png`。示例内容固定，离线可运行；生成 PNG 后即可直接检查布局。

运行方式（在仓库根目录）：

```powershell
& 'C:\Users\liwanqing\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' firmware/tools/preview_weather.py
```

也可用 `-o` 指定输出文件。改天气布局时，应先更新预览、打开图检查，再运行固件编译和刷机。

## 精度边界

当前脚本是最小布局预览，不是设备截图，也不是固件 C++ Renderer 的逐像素仿真。它复刻了页面分区和四种墨水色，中文字体来自 Windows 字体，图标由简单图形代替；因此可发现大块布局错误，但字宽、字形、图标、主题细节可能和真机不同。仓库里的旧 `firmware/screen_preview.py` 同样是手工绘制，不应当作当前天气固件的准确预览。

## 下一步：把预览变成可信的刷机门禁

1. 在主机侧做一个很小的预览程序，输入固定的天气 JSON 样例，创建 400×300 framebuffer，并调用固件现有的 `WeatherRenderer::Render()`。
2. 复用同一份 `rawdraw` 绘图代码和固件字体资源；只替换 ESP-IDF/FreeRTOS 外围依赖，不复制页面坐标或重新实现天气布局。
3. 按真实 2bpp 编码导出 PNG，映射为白、黑、黄、红，并保留固件使用的字形与图标。图片生成后在工作区显示，便于开发者和用户共同检查。
4. 增加无天气数据、AQI 缺失、超长城市名等少量固定样例；至少检查图像尺寸、颜色集合和关键区块不重叠。
5. 预览确认后再编译、刷板。若主机侧不能直接链接 LVGL 字体，则先做一个针对单页的薄适配层，所有布局和绘图仍由 `WeatherRenderer` 执行。

## 完成标准

- 一条命令生成 PNG，不需要设备在线或刷机。
- 预览图由固件天气 Renderer 实际绘制，布局不在 Python 中另写一份。
- PNG 为 400×300，只含设备支持的四种颜色，中文与天气图标来自固件资源。
- 代码调整天气页后可在刷机前重复生成、展示和检查该图。
