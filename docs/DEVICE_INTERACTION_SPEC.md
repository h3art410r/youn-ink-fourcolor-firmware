# NOTE4C 双应用交互规格

## 第一版范围

当前主应用轮播为天气、备忘录，顺序固定；设备页面标题显示当前应用序号（1/2、2/2）。相册暂时不在按键轮播中显示，但相册功能保留：网页选中照片仍可在设备上打开，传图模式也保持可用。天气数据源配置继续由局域网管理页负责；日历、设备状态卡等想法留待后续。

设备直接显示一个全屏应用，不经过功能菜单。启动默认进入天气；退出传图模式后也回到天气。

| 按键 | 天气 | 备忘录 |
| --- | --- | --- |
| 上键单击 | 上一个应用 | 上一个应用 |
| 下键单击 | 下一个应用 | 下一个应用 |
| BOOT 单击 | 切换上海/杭州 | 显示下一条备忘 |

第一版的核心导航只用单击，不依赖双击或长按，也不增加返回键。

## 刷新规则

四色屏全屏刷新很慢。刷新期间按键仍可改变目标应用或内容，当前刷新完成后只显示最后的目标，不逐一刷新中间状态。该策略避免输入被吞掉或排队触发多次无用刷新，但不会缩短正在进行的屏幕刷新时间。

## 天气数据

默认使用 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)，按城市经纬度请求当前天气和四天预报，不需要 token。免费接口用于非商业用途；天气数据采用 [CC BY 4.0](https://open-meteo.com/en/license)，天气页显示数据来源。设备网页也可切换到和风天气，配置专属 API Host 和 API Key；凭证保存在设备 NVS，GET 接口只返回是否已配置，不返回凭证值。第一版不在设备上生成或签名 JWT。

天气页使用统一的 `WeatherData` 数据结构和回调；数据提供方只在客户端适配层切换，不改页面交互和绘制。管理页地址是设备当前 Wi-Fi 地址的 HTTP 80 端口，包含照片管理、相册轮播和天气来源配置。当前为局域网明文 HTTP，凭证仅应在可信局域网配置。

## 备忘录应用

备忘录是独立的全屏应用，与相册并列。屏幕只负责阅读，管理网页负责新增、编辑、排序和删除；这样不需要在慢刷新的墨水屏上编辑文字。

- 上键/下键在应用间切换；BOOT 在备忘录中显示下一条，列表循环。
- 一屏只显示一条：标题醒目、正文自动换行，底部显示当前序号和“BOOT 下一条”；不增加详情层级或返回操作。
- 没有内容时显示“暂无备忘，请在管理页添加”，不显示空白页。
- 网页中提供标题和正文编辑区，支持新增、编辑、调整顺序、删除；保存后当前备忘录页立即刷新。
- 第一版限制为最多 8 条，标题最多 20 个汉字左右，正文最多约 50 个汉字，避免挤压屏幕阅读和设备存储。

## 后续原则

- 应用保持全屏直达，优先展示偶尔查看、内容稳定的信息。
- BOOT 在各应用中执行一个简单、可逆的主要动作。
- 不把实时滚动、频繁操作或深层菜单作为目标场景。
- 相册的图片计数与应用序号是不同状态；相册从主轮播隐藏时仍可由网页点选照片直接进入，上下键不会用于相册翻页。
- 新应用按相同的应用切换与内容切换约定接入。
