# NOTE4C 两应用交互规格

## 第一版范围

第一版只开放相册和天气。日历、设备状态卡等想法保留为后续扩展，不进入本次实现。

设备直接显示一个全屏应用，不经过功能菜单。启动默认进入相册。

| 按键 | 相册 | 天气 |
| --- | --- | --- |
| 上键单击 | 切换到天气 | 切换到相册 |
| 下键单击 | 切换到天气 | 切换到相册 |
| BOOT 单击 | 显示下一张图片 | 切换城市并显示该城市天气 |

天气城市固定为上海和杭州，BOOT 在两者间循环。第一版的核心导航只用单击，不依赖双击或长按，也不增加返回键。

## 刷新规则

四色屏全屏刷新很慢。刷新期间按键仍可改变目标应用或内容，当前刷新完成后只显示最后的目标，不逐一刷新中间状态。该策略避免输入被吞掉或排队触发多次无用刷新，但不会缩短正在进行的屏幕刷新时间。

## 天气数据

默认使用 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)，按城市经纬度请求当前天气和四天预报，不需要 token。免费接口用于非商业用途；天气数据采用 [CC BY 4.0](https://open-meteo.com/en/license)，天气页显示数据来源。设备网页也可切换到和风天气，配置专属 API Host 和 API Key；凭证保存在设备 NVS，GET 接口只返回是否已配置，不返回凭证值。第一版不在设备上生成或签名 JWT。

天气页使用统一的 `WeatherData` 数据结构和回调；数据提供方只在客户端适配层切换，不改页面交互和绘制。管理页地址是设备当前 Wi-Fi 地址的 HTTP 80 端口，包含照片管理、相册轮播和天气来源配置。当前为局域网明文 HTTP，凭证仅应在可信局域网配置。

## 后续原则

- 应用保持全屏直达，优先展示偶尔查看、内容稳定的信息。
- BOOT 在各应用中执行一个简单、可逆的主要动作。
- 不把实时滚动、频繁操作或深层菜单作为目标场景。
- 新应用按相同的应用切换与内容切换约定接入。
